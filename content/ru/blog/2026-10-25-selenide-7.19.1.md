### Подарок на день рождения: поддержка Java 11 {#java-11}

Да-да, мы знаем. На дворе 2026 год. Но где-то ещё живут несчастные динозавры, которые гоняют тесты на Java 11.

### Настройка `Configuration.timezone` {#timezone}

В [Selenide 7.19.0](/2026/10/10/selenide-7.19.0/#mock-clock) мы добавили метод `clock().setTimezone()`.
Но он меняет часовой пояс только в текущей вкладке.

Теперь есть настройка, которая задаёт часовой пояс для всего браузера - всех вкладок, окон и воркеров:

```java
Configuration.timezone = "America/New_York";
// либо -Dselenide.timezone=America/New_York
```

Как это работает:
* Локальный Chrome, Edge или Firefox запускается с переменной окружения `TZ`
  (браузеры на Windows её игнорируют, поэтому на Windows Selenide просто пишет предупреждение в лог).
* Удалённый браузер получает capability `se:timeZone` (поддерживается Selenium Grid в Docker).
* Если вы используете capabilities `selenoid:options` или `moon:options`, в них тоже добавляется `timeZone`.
* Принимаются только ID из tz database (вроде `Europe/Tallinn`). Неправильный часовой пояс сразу вызывает ошибку.

См. [issue 3475](https://github.com/selenide/selenide/issues/3475) и [PR 3476](https://github.com/selenide/selenide/pull/3476).

### Опция `--timezone` в Selenide CLI и MCP {#cli-mcp-timezone}

Та же настройка теперь доступна в [Selenide CLI](/2026/08/20/selenide-7.18.0/#selenide-cli)
и [Selenide MCP-сервере](/2026/04/10/selenide-7.16.0/#selenide-mcp-server):

```shell
selenide open --timezone=Asia/Tokyo https://selenide.org
```

См. [issue 3475](https://github.com/selenide/selenide/issues/3475) и [PR 3476](https://github.com/selenide/selenide/pull/3476).

### Selenide CLI skill: дампы HTML-страниц {#cli-skill-html-dumps}

В Selenide CLI skill теперь описаны дампы HTML-страниц.
Теперь ваш AI-агент будет знать, что не стоит каждый раз делать скриншот и пытаться его анализировать как картинку.
Вместо этого он должен сообразить, что дешевле анализировать "*.html" файл.

См. [PR 3481](https://github.com/selenide/selenide/pull/3481).

<br>

### Подчищаем память в `SelenideLogger` {#selenide-logger-leak}

Когда у потока удалялся последний листенер, `SelenideLogger` всё равно хранил для этого потока пустую запись.
При большом количестве потоков такие записи могли накапливаться. Теперь запись потока удаляется вместе с его последним листенером.

Спасибо [Matthias Kurz](https://github.com/mkurz) за [PR 3463](https://github.com/selenide/selenide/pull/3463)!
