### Сохранение и восстановление состояния браузера {#browser-state}

Многие тесты начинаются с логина. А логин занимает время.
Ну знаете, открыть логин-форму, ввести пароль, получить как-то email или SMS и т.д.

> Самое лучшее решение - это, конечно, сделать способ быстрого логина без лишних телодвижений. Об этом в былые времена я рассказывал 
> [на моём любимом Selenium Camp](https://www.youtube.com/watch?v=ePvrXUCeAr8&t=38m27s), например. 

Увы, оно доступно не всем. Поэтому для массового автоматизатора теперь есть способ попроще: 
один раз залогиниться и сохранить состояние браузера в файл, а в каждом последующем тесте его восстанавливать.

Мы постарались сделать в Selenide таксимально короткий API для этого:

```java
open("/dashboard", withBrowserState("build/auth.json")
  .loggedInIf(() -> $("#logout").is(visible, Duration.ofSeconds(2)))
  .orLogin(() -> login("bob", "secret")));
```

Как это работает:
1. Если файл `build/auth.json` есть, Selenide восстанавливает из него куки, `localStorage` и `sessionStorage`, открывает страницу и проверяет условие `loggedInIf`.
2. Если файла нет или проверка не прошла (протухла кука, перезапустился сервер, отозвали сессию), Selenide
   чистит старое состояние, вызывает `login`, сохраняет новое состояние в файл и снова открывает страницу. И ваш браузер готов к работе. 
3. Если проверка не прошла даже сразу после логина, вы получите понятную ошибку (а не бесконечный цикл).

Работает и в параллельных тестах: логинится только один поток, остальные переиспользуют его состояние.

Если логика "залогиниться при необходимости" не нужна, можно просто восстановить состояние:

```java
open("/dashboard", withBrowserState("build/auth.json"));
```

Если вы лямбды не уважаете, есть и низкоуровневый API. Тупо два метода "сохрани" и "восстанови":

```java
webdriver().saveBrowserState(Path.of("build/auth.json"));
webdriver().restoreBrowserState(fromFile("build/auth.json"));
BrowserState state = webdriver().getBrowserState();
```

P.S. Если что, класс `WebDriverConditional` переименовался в `BrowserSession`, и метод `webdriver()` теперь возвращает его.
Ваш код скомпилируется без изменений, но библиотеки, скомпилированные со старой версией Selenide, придётся перекомпилировать.

Спасибо [jinlxz](https://github.com/jinlxz) за идею!

См. [issue 3378](https://github.com/selenide/selenide/issues/3378) и [PR 3461](https://github.com/selenide/selenide/pull/3461).

### Эмуляция времени и часового пояса {#mock-clock}

Как протестировать страницу, которая пишет "Доброе утро" только утром? Или баннер "ваша подписка истекает завтра"?
Теперь есть метод `clock()`:

```java
import static com.codeborne.selenide.Selenide.clock;

clock().setTimezone("America/New_York");
clock().setFixedTime(Instant.parse("2025-01-15T14:00:00Z")); // 9:00 утра в Нью-Йорке

open("/dashboard");
$("[data-testid=greeting]").shouldHave(text("Good morning, 9:00 AM"));

clock().reset();
```

* `setFixedTime` замораживает `new Date()` и `Date.now()` для вновь загружаемых страниц.
* Работает в Chrome и Edge (через CDP) и в Firefox (через BiDi).
* `reset()` можно спокойно вызывать в `@AfterEach` для любого браузера.

Спасибо [Nigel](https://github.com/youvegotnigel) за идею и [suhanrain](https://github.com/suhanrain) за реализацию!

См. [issue 3370](https://github.com/selenide/selenide/issues/3370), [PR 3431](https://github.com/selenide/selenide/pull/3431)
и [PR 3442](https://github.com/selenide/selenide/pull/3442).

### Условия `visibleText` и `exactVisibleText` {#visible-text}

Условие `text()` проверяет весь текст элемента, даже если часть его обрезана через CSS (`overflow: hidden`, `text-overflow: ellipsis`).

```java
// Пользователь видит:
"Пневмония не…"

// Тест радостно проходит с:
text("Пневмония неизвестного происхождения");
```
Теперь можно проверить только тот текст, который реально виден на экране:

```java
$(".product-name").shouldHave(visibleText("Пневмония неиз"));
$(".product-name").shouldHave(exactVisibleText("Пневмония неиз…"));
```

Старые условия `text()` и `exactText()` работают как раньше.

Спасибо [svasenkov](https://github.com/svasenkov) за реализацию!

См. [issue 1741](https://github.com/selenide/selenide/issues/1741) и [PR 3366](https://github.com/selenide/selenide/pull/3366).

### HtmlUnit вернулся {#htmlunit}

Когда-то Selenide поддерживал HtmlUnit из коробки, но мы его выпилили из-за размера. Ну и как будто проект казался мёртвым какое-то время.
Теперь он вернулся, но как опциональная зависимость. Если хотите гонять тесты в HtmlUnit, добавьте зависимость:

```groovy
testImplementation("org.seleniumhq.selenium:htmlunit3-driver:4.48.0")
```

и поставьте 
```java
Configuration.browser = "htmlunit";
// либо -Dselenide.browser=htmlunit
```

Конечно, HtmlUnit - не настоящий браузер: shadow DOM, лейаут, координаты, hover и т.п. там не работают.
Но для простых страниц это может быть быстрый вариант прогнать тесты вообще без браузера.

См. [PR 3470](https://github.com/selenide/selenide/pull/3470).

### Capabilities браузера в MCP и CLI {#mcp-cli-capabilities}

У [Selenide MCP](/2026/04/10/selenide-7.16.0/#selenide-mcp-server) и [Selenide CLI](/2026/08/20/selenide-7.18.0/#selenide-cli)
появился параметр `--capability=<name>=<value>`. Его можно повторять, а значения, начинающиеся с `{` или `[`, парсятся как JSON,
так что можно передавать вложенные capabilities:

```shell
selenide open --capability='goog:chromeOptions={"args":["--no-sandbox"]}' https://selenide.org
selenide open --capability='selenoid:options={"enableVNC":true}' https://selenide.org
```

Переданные так аргументы Chrome добавляются к дефолтным аргументам Selenide, а не заменяют их.

См. [PR 3459](https://github.com/selenide/selenide/pull/3459).

### Старые временные файлы больше не ломают скачивание {#stale-download-files}

Если скачивание файла падало, браузер мог оставить в папке загрузок временный файл (`.crdownload`, `.tmp`, `.part`).
И после этого падали _все_ последующие скачивания с `FileNotDownloadedError` (это могло быть проблемой, только если вы используете свой вебдрайвер через `setWebDriver()`).

Теперь Selenide игнорирует временные файлы, которые были в папке до начала скачивания.
А если не может почистить папку загрузок (например, на Windows браузер всё ещё держит файл), то просто пишет предупреждение в лог вместо исключения.

Спасибо [ilya-corp](https://github.com/ilya-corp) за репорт!

См. [issue 2675](https://github.com/selenide/selenide/issues/2675) и [PR 3457](https://github.com/selenide/selenide/pull/3457).

### Уникальные имена файлов для скриншотов и логов {#unique-file-names}

Некоторые имена файлов (скриншоты, папки загрузок, `webdriver.*.log`) генерировались только из текущего времени.
Поэтому два потока теоретически могли в одну и ту же миллисекунду создать файл с одинаковым именем, и один файл затирал другой.

Теперь в имена файлов добавляется ещё и уникальный счётчик.

См. [PR 3469](https://github.com/selenide/selenide/pull/3469).

### Appium: `scroll()` и `swipe()` внутри элемента {#appium-scroll-inside}

До сих пор скролл и свайп в Appium всегда выполнялись по всему экрану.
Теперь их можно выполнить внутри заданного элемента:

```java
$(By.xpath(".//*[@text='Tabs']")).scroll(down().inside($(By.id("android:id/list"))));
$(By.xpath(".//*[@text='TAB 12']")).swipe(right(10).inside($(By.id("android:id/tabs"))));
```

Если контейнер частично вылезает за экран, жест выполняется только в его видимой части.

Спасибо [valentin-kudin](https://github.com/valentin-kudin) за реализацию!

См. [issue 3445](https://github.com/selenide/selenide/issues/3445), [PR 3446](https://github.com/selenide/selenide/pull/3446)
и [PR 3455](https://github.com/selenide/selenide/pull/3455).

### Appium: цепочечные методы возвращают `SelenideAppiumElement` {#appium-chainable-methods}

Раньше такой код не компилировался, потому что `setValue` возвращал `SelenideElement`:

```java
SelenideAppium.$(By.id("amount")).setValue("100").tap();
```

Теперь 27 цепочечных методов (`setValue`, `val`, `type`, `append`, `press*`, `click`, `doubleClick`, `hover`, `scroll` и т.д.)
возвращают `SelenideAppiumElement`.

Спасибо [aquahitt](https://github.com/aquahitt) за реализацию!

См. [issue 3440](https://github.com/selenide/selenide/issues/3440) и [PR 3441](https://github.com/selenide/selenide/pull/3441).

<br>

### Appium: свой класс элемента в `SelenideAppiumCollection` {#appium-custom-collection}

Если у вас есть свой интерфейс элемента, наследующий `SelenideAppiumElement`, теперь можно создать и соответствующую коллекцию:
у `SelenideAppiumCollection` появился `protected` конструктор, принимающий класс элемента
(такой же, какой появился у `ElementsCollection` в [Selenide 7.17.0](/2026/07/12/selenide-7.17.0/)).

Спасибо [aquahitt](https://github.com/aquahitt) за реализацию!

См. [issue 3438](https://github.com/selenide/selenide/issues/3438), [PR 3439](https://github.com/selenide/selenide/pull/3439)
и [PR 3447](https://github.com/selenide/selenide/pull/3447).

### Обновили Appium java-client с 10.1.1 до 11.0.0 {#update-to-appium-11}

В Appium java-client 11 есть ломающие изменения, но Selenide прячет их от вас:
* `SelenideAppiumPageFactory` работает с новым `FieldDecorator`;
* чтение/запись буфера обмена по-прежнему работает со старыми Appium-серверами (например, на BrowserStack).

См. [PR 3467](https://github.com/selenide/selenide/pull/3467).
